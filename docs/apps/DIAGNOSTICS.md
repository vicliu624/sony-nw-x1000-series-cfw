# Diagnostics and minimal applications

## Parent-process entry capsules (local only)

The failed external probes could not distinguish failure before exec from
storage/preflight refusal. `compose_parent_entry_trace.py --host-review ...`
instead builds an explicitly separate diagnostic ELF with five getpid observer
calls inside the original player's Home entry, name-query entry/return and
switch entry/return. It changes four declared instructions and places248 bytes
in a verified empty RX-only slot; ELF size and original headers do not grow.
The capsule restores its temporary frame, volatile arguments, LR and condition
flags before executing the displaced instruction. It does not alter the
original APF decision or wait for an external app to start.

The capsules are **not paired with the real host dispatcher/USB guard yet** and
are not deployable. The separate observer/storage pairing is tested below.
Ordinary getpid without a paired observer produces no persistent evidence.
It is not an external app or a public SDK capability. Do not ask a user to
install this ELF or present it as a repaired/trace-enabled firmware.
`test_parent_entry_trace.py --review ...` compares original/traced ARM boundary
states across21 cases, including arbitrary observer returns and failing APF
results. The optional --parent-trace-review on test_current_home_switch_mode.py
executes all five capsules with the original name client/manager parser; file
operations, IPC transport and observer effects remain fixtures. No complete
original GUI, process retirement or hardware qualification is implied.

The separate parent_trace_store C backend writes only an existing2048-byte
`/contents/HOMEBREW/data/diagnostics/parent-boundary.bin`. Initialization opens
no file. A mandatory trusted callback must confirm Linux/USB storage ownership
before opening and again before writing; it cannot default to success. The
backend additionally checks the expected /contents VFAT mount, rejects nested
or duplicate mounts, rejects symlink components, compares device/inode/link
count, and requires the exact size and caller-supplied32-byte identity header.
It never creates, truncates, appends or falls back to a system path.

Stage1 arms recording. Each of16 stages has at most one write attempt per
context, guarded by trylock; each fixed slot is64 bytes and must be empty.
Header bytes0..31 and reserved tail1056..2047 are never written. Records contain
HBP1, stage, sequence, twelve caller-supplied32-bit payload values and CRC32.
Every opened record FD is closed in the same call, including refused/failed
writes; errno is preserved. No worker/timer or persistent log FD is created.
This bounds IO count and file growth, not kernel/filesystem blocking duration.

`test_parent_trace_store.py` runs Sony libc/LinuxThreads and the actual stat
bridge under generic ARM Linux. RAM storage, mount text and the ownership
predicate are fixtures. It checks all16 slots, independent CRCs, unchanged
header/tail, existing slots, absent/wrong-size/nonce/symlink files, lost owner,
read-only/wrong-device/nested/duplicate mounts, lock contention, short writes
and fsync failure. The PC-only `read_parent_entry_trace.py --seed ... --trace ...`
requires copied work/ files, rejects wrong identity/size/tail and reports
partial/bad-CRC slots without discarding other valid records. An empty trace is
inconclusive. Real ownership checks, parent dispatcher pairing and physical
VFAT/USB timing still require integration; no firmware is generated by tests.

The private parent_trace_observer accepts only the exact stage/tag/caller map
and matching capsule bytes. It also requires the frame address to equal the
PID shim's captured entry-SP+8 before copying five saved register words. A
read-only snapshot callback may supply seven additional numeric values;
failure leaves explicit unknowns. There is no retained stack pointer, resource
grant or original-result rewrite. Trusted image/ownership callbacks and their
context must remain alive for the initialized observer.

`XW_PLAYER_PARENT_TRACE` is an opt-in diagnostic assembly ABI requiring argument
capture. It passes entry SP as a sixth private dispatcher argument. Without
this flag, both original four/five-argument text and relocations are unchanged.
The normal host_hook.c does not implement that diagnostic dispatcher yet.
`test_parent_trace_observer.py --capsule-review ...` links the exact capsule
bytes and actual diagnostic shim to the observer/backend under ARM/Sony libc.
It reads back stages1..5 with matching CRC, rejects bad caller/frame/image, and
checks that denied storage leaves the fixture native return unchanged.
Continuation targets, dispatcher, numeric snapshot and ownership are fixtures;
this test does not run the original GUI or establish physical USB ownership.

Source is separated under runtime/apps/diagnostics, graphics-demo, key-check and
hello. Shared PCM ownership probes live with diagnostics; shared adapters remain
under runtime/native and runtime/platform.

Graphics Demo demonstrates ordinary C main, original-libc startup, a private
framebuffer surface, touch handling and return to the launcher. Hello is a console
ABI example. Key Check reports the verified event interface; names/numbers are
Sony-specific. Diagnostics are tools, not a promise of safe arbitrary hardware
experimentation.

## Launcher entry stages

`tools/build_libc_frontend.py --entry-trace --managed-radio-review
--review-output work/<unused-review-directory>` builds an explicit diagnostic
launcher. Stderr markers identify main entry, native entry, completion of HOME
device open, signal setup, catalog scan, display setup, first draw/presentation
and session return. The original operations and return decisions remain in
place. This build opens no log file and keeps no persistent storage descriptor.
It does not automatically capture stderr on a physical player; a separately
reviewed capture mechanism is still required before asking for hardware tests.

`tools/probe_stock_proxy_system.py --launcher --launcher-review <build.json>
--output work/<unused-test-directory>` executes the supplied ELF through Sony's
unchanged appproxy and checks the diagnostic stage order when enabled. The
generic ARM guest interposes display/touch and provides one fixture app; it
does not qualify the real player-to-manager transition or physical drivers.
Leave entry tracing disabled for ordinary builds. The no-trace rebuild was
byte-identical to the installed launcher, not merely behaviorally equivalent.

`tools/build_launcher_capture.py` prepares a separate C capture supervisor and
a nonce-matched4096-byte seed file in ignored work/. It may overwrite at most
4000 bytes after the32-byte header in that existing file. It never creates or
enlarges it. Before writing it checks the user mount, rejects nested mounts,
checks non-symlink directory components, filesystem identity distinct from
root, exact size, link count, inode and nonce. The child path is fixed to
`/contents/HOMEBREW/launcher/entry-trace-app`; child symlinks are rejected.
It captures stderr through a pipe and records exec errno and wait status.
After a finite polling budget or output limit it terminates its child process
group and reaps the child. Blocking filesystem calls are not a guaranteed
wall-clock deadline. Do not tap app entries during a diagnostic session.

This program is not deployed by normal builders. Installation/execution needs
separate approval and an exact reviewed launcher binary. It cannot observe a
stock switch that never starts it, and a storage-preflight refusal produces
no file record. It temporarily holds the user-file descriptor while capturing;
it is not a production logging or sleep/USB ownership design.
`tools/test_launcher_capture_system.py --review <build.json>` tests real ARM
process/file behavior with original libc, a RAM volume and synthetic mount
listing. Coverage includes child exit, missing executable, closed-stderr
hang, output overflow, absent user mount, symlink rejection and wrong nonce.
The generic guest also sends SIGTERM while the supervisor is capturing an idle
child, verifies the recorded/reaped child termination and checks PID1 has no
remaining adopted diagnostic child. This is not physical APF/USB qualification
and does not authorize interaction with app entries during the diagnostic.
`tools/read_launcher_capture.py --review <build.json> --trace <copied-file>`
decodes the record on the PC without contacting a device. A decoded record is
evidence of reached stages, never proof of hardware qualification.

For a combined offline run, add `--launcher-capture-review <capture-build.json>`
to the original-proxy runner alongside `--launcher --launcher-review
<traced-launcher-build.json>`. This explicitly mounts a RAM user volume in the
guest and interposes only the mount-list stdio read in addition to modeled
display/touch. The unchanged original proxy launches the exact supervisor;
its child then uses the traced launcher. The peer reads the finished record
after proxy exit, so console replay order must not be mistaken for live timing.
It is not a Sony hardware or VFAT emulator.

`tools/Use-LauncherCapture.ps1` defaults to `-Mode Preview`. Explicit `Install`
and `Restore` modes are restricted to the reviewed diagnostic files, expected
Sony serial and user-volume identity. Installation retains the exact original
launcher on both PC and user volume, validates staged hashes and refuses
existing temporary paths. Restore copies the record to PC before restoring
the original hash and removing recognized temporary files. It does not execute
device programs or flash. These mutation modes require separate authorization;
their existence is not permission to run them. `Test-LauncherCaptureInstall.ps1`
exercises the unchanged script under an isolated local fixture with a substituted
USB evidence reader; it never contacts the player.

Use their builders' safe CLI entries and offline fixtures before any hardware
entry. An inspection option must not implicitly enable an ioctl, power change or
device write. A successful stdout/selftest result does not qualify Sony Home,
USB/sleep handoff, sound or recovery. Do not run an app's graphics entry while
WiFi Terminal owns the display.
