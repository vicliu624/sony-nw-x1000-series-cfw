# Japanese 1.11 SD8686 bindings

This reference describes the original Linux driver and separate radio CPU.
Use the [transport overview](../ESPNOW_IMPLEMENTATION.md),
[endpoint contract](../ESPNOW_FULL_STACK.md) and
[current status](../STATUS.md) before composing a firmware or device test.
Addresses are radio CPU addresses unless marked Linux-module section offsets
or ESP32-S3 addresses. They are not interchangeable with Linux process pointers.

## Original identities and container

| Input | Bytes | SHA-256 |
| --- | ---: | --- |
| `sd8686.bin` | 123,980 | `08f1a0ba5ce3895324899c88a2b0c05b7c1b843ac61e6a6eec530c2463395f3a` |
| `sd8686.ko` | 192,572 | `2cce84755878b1f697491d00f4c3e23829d3a1271b3bf8a634ceb88fe3928a69` |

Embedded firmware ID is `sd8686-B0,RF868X,FP4,9.70.3.p32`, build 2008/07/08.
Recorded driver identity is `sd8686-9.70.3.p32-26409.p51-(FP4)`. These software
strings do not independently identify physical package/stepping.

`tools/marvell_firmware.py` parses records containing LE32 command/address/
length and a big-endian header CRC. Command-1 length includes a big-endian
payload CRC trailer. Both CRCs use MSB-first polynomial `0x04c11db7`, initial
zero and no final XOR. Original input has 238 valid header and 237 payload
checks; strict parse/serialize is byte-identical. Damage, truncation, address
wrap and trailing bytes are rejected.

The original loader accepts `fw_dir`, passes `helper_name`/`fw_name`, and the
driver reads files through `filp_open`. Radio-only experiments can use that
loading route from verified user storage. It drops ordinary connectivity while
reloading. A system UPG, live instruction patch or guessed RAM gap is not needed
for that separate laboratory path.

## Linux and command boundary

| Binding | Observed behavior |
| --- | --- |
| Driver section `0xa8f4` | AUTO/ADHOC/INFRA mode handling; monitor mode 6 rejected |
| Driver section `0x3ce8`, ioctl `0x8be4` | Private hostcmd buffer through QueueCmd and response copy; no command-ID whitelist observed in this wrapper |
| `ProcessRxedPacket` | Ethernet `eth_type_trans` / `netif_rx`, not a raw Action-frame API |
| Driver section `0x19710`, `sbi_get_int_status` | Actual SDIO read/demultiplex: data 0, command 1, event 3; `sbi_card_to_host` is a stub |
| Radio `0x8078` | Strip eight-byte command header and dispatch command masked with `0x7fff` |
| Command `0x0098` | Original dispatch takes default `0x9b24`, result 2 / response `0x8098`; neighboring 0x0096/97 have handlers |
| Command `0x0086`, `0x88d6` | Addressed word access: action 0 reads through `0x88ea..0x88ee`; only action 1 writes |

The native word adapter uses a validated 20-byte command envelope. Public SDK
operations do not expose arbitrary memory reads/writes. The observed private
driver table contains 114 records; no stock monitor/raw Action API was named.
An AF_PACKET socket owns a native filter reference but does not supply the
radio's internal management objects as payloads.

`wlan_hostcmd_ioctl` response path `0x3f38..0x3f9c` copies the response header's
declared size and updates `iwreq.u.data.length` at `0x3f8c`. A 1,500-byte request
can therefore return a 36-byte frame-submit reply. Copy failure can still reach
return zero and the length update; check the response command, length, result and
echoes before publishing anything. `tools/test_sd8686_hostcmd_response.py`
executes this original response path with modeled copy/free functions. It does
not execute command-queue waits, signal interruption or hardware.

## Native filter and activation state

Stock adapter field +`0x13c4` initializes to `0x0203`, not `0x0003`.
Original station setup's observed command prefix is `0003,0028,0074,0076,001e`.
The MAC_CONTROL builder at driver `0xc388..0xc3b8` creates command `0x0028`,
size 12, with supplied flags at byte 8. Replacing the whole word discards
unrelated stock state.

`wlan_set_multicast_list` at driver +`0x770` maps netdev `0x100` to command
`0x80`, and netdev `0x200` to command `0x100`, preserving other filter bits.
Use scoped stock membership and cleanup rather than guessed flag writes.

Let F be word `0xc0014528`, P the byte through
`*(0xc000ee48) -> +8 -> +0xc0`, Q byte `0xc00146e0`, A byte `0xc0014684`,
K byte `0xc0014686`, and R byte `0xc0007883`:

| Operation | Original-instruction observation |
| --- | --- |
| MAC flags | Existing F `0x8000` preserved |
| Flag `0x80` | Save `0x8000a300` to `0xc000ee00`, OR `0x0b`; clear restores backup only when nonzero |
| Flag `0x100` | Set/clear register mask `0x40` |
| `0x54c0` | Select `0xa698` when `(F&8) || P || (A!=0 && K==2)`, setting `0x8000200c` mask `0x4300`; `0xa674` clears it |
| `0x6b6c` | Select `0xdc94` when `(F&8) || (P!=0 && Q!=0) || (R==2 && A!=0 && K==2)`, setting `0x8000a300` mask `0x200`; `0xdd10` clears it |

The formulas differ. Clearing one command bit does not select both clear paths.
Repeated `0x80` enable also overwrites its saved register value: fixture sequence
`80,0` restores `0x10000000`, but `80,80,0` restores `0x1000000b`.
Upstream names such as WEP/promiscuous/all-multicast do not independently prove
this firmware's unknown-key Protected-frame admission or complete crypto behavior.

Activation helper `0xc5e4` clears bytes `0xc0014684/86` for its first selector,
`0xc0014685/87` for its second, Q for the first, and command flag `0x0400` when
either is set. It preserves `0x0008` and performs no observed MMIO writes.
Wrapper `0xc0006144` calls it with `(1,1)`, then `0x54c0`/`0x6b6c`. P remains
separate: with P=1 the modeled `0x4300` mask remains, plus writes to
`0x8000a320=7` and `0x8000a350/354=0xffffffff`; Q reset clears the other mask.
This is activation-state reset, not established key-buffer/hardware-slot erasure.

Connection-result code `0xc0004cd8` can copy `0xc00078c8` to P and update Q/e1.
The CMD005e parser at `0xc00048c8` routes type-`0x0100` TLVs to key handler
`0xc720`; it is distinct from activation reset. Diagnostic comparisons therefore
need flags, activation bytes, Q, bounded P and both numeric registers together.
The fixed [Radio Inspect](../../runtime/platform/espnow/inspect/README.md)
reader is GET-only and has offline coverage; no physical qualification follows
from equal samples or a partial fingerprint.

## Frame dispatch and packet ownership

The MAC Mgmt task entry `0xc0003188` is registered as task 4. Its
`0xc000323a..0xc0003288` clause polls through `0xe164` and copies with `0x4b9c`,
then reaches subtype dispatch `0xa314` through veneer `0xc00026a8` / target word
`0xc00026b0`. Action subtype 13 maps to internal event 2 for SyncSrvSta
`0xc000752c`. Constructor `0x5648` configures its states; Bss_Active `0x1f00`
and IBss_Active `0x3404` pass event 2 to `0x136b0`.

Original handler `0x136b0` consumes category 0, has a specialized category-17
path, and can copy other categories below 128 into a packet with bit `0x80`
set. Thus ESP-NOW category 127 can become 255. Recorded automatic replies prove
that path, not application delivery. Parsers `0xc0003004/30b0` recognize WMM
OUI `00:50:f2`, not an ESP-NOW application codec.

TX ownership follows allocator `0xd458`, header builder `0xda00`, submit
`0xd800`, queue helper `0x1571c`, queue 3 / task 5 event 2. Submit owns the
packet on success and queue rejection; do not free it again after rejection.
Queue admission differs from original MAC completion and peer receipt.
The opt-in FRM1 path uses the same queue helper/notification and original free,
but cancels custom tracking before a rejected packet is freed. Its completion
observer claims the aligned pointer before free and retains that claim until
publication. An unrelated release of a reused address cannot publish the claim.
Its command entry fits inside the replaced command0x86 case, ending before
0x88f2; the generated profile fingerprints that complete case. No additional
pool reservation is implied. The [performance contract](ESPNOW_PERFORMANCE.md)
describes native reconciliation and the remaining hardware limits.
Host reply helper `0xc00062f0` uses the queue ID at `0xc00078b4`, notifying task 0
event 20. Its pool `0xc000d604` has one 342-byte block and must not be borrowed
permanently. Borrowed RX work has a separate lifetime.

### Reserved memory

| Property | Original | Matched candidate |
| --- | --- | --- |
| Large pool manager | `0xc000d5a4` | Same |
| Pool base / stride | `0xc0008b4c` / 1,900 bytes | Same |
| Large blocks | 4 | 3 |
| Reserved interval | None | `[0xc000a190,0xc000a8fc)` |

Pool initializer `0x163ec` calls `0x10294`; block count is patched at `0x163ee`.
Allocator `0x102dc` and release `0x1031c` are checked with substituted IRQ effects.
The raw pool allocator's fourth request in the three-block replay returns zero.
Its node pointer differs from the packet factory's data pointer at block+140.
Native validation checks that data pointer's back-reference at -4, node at -136,
node data at +8 and descriptor `0xc0014728` at +24 before packet access.
The callback target and two scatter-zero entries must change with the pool count.
Original BSS `0xc0006e70..0xc0017da4` is split around the reservation; a formerly
zero-length entry supplies the second range. No new SRAM is assumed.

`0xc0000e00..0xc0001000` is not approved scratch space: a recorded survey found
128 nonzero words without identifying an owner. Appending after low `0x17340`
also conflicts with unqualified stack/RTOS use near `0x17d14..0x17d3c`. Cache
configuration at boot does not qualify live instruction patching.

Runtime stock verification uses four-block layout plus 276 stable code/layout
bytes: SHA-256 `ea3548def031c67fede1ff197fd2def4f71b1b6b9932c3712c54b58ee1fa5580`.
Consumed startup data `0x17320..0x17340` is excluded: `0x11e0/11f4` clears
831 words at `0x17304..0x18000`. Those bytes remain checked offline when building
the image. The stable digest is partial attestation, not full RAM integrity.

### Full receive backend

The singleton RX-work pool is at `0xc000d5ec`, one 1,700-byte slot at
`0xc000cdac`. Expected context is slot+40 (`0xc000cdd4`), frame slot+92
(`0xc000ce08`); node `0xc000cdb0` contains frame and descriptor `0xc0014710`.
The full hook checks that ownership before copying into its own large-pool packet.

Its internal wrapper has length at +0, frame control at +2/+3, A1 at +6,
source at +12, A3 at +18, fragment bits at +24 and retained body at +32.
Body size is length minus 48; it checks length 63..1584, Action/unfragmented
form, broadcast A3, local/broadcast A1 and the supported envelope. Own MAC is
obtained through pointer `0x04001bc4`. Protected traffic requires local unicast.
These are internal wrapper offsets, not raw pcap/socket offsets.

The single MAC producer enters under the original IRQ token. Stop writes
enabled=0, waits producer_active=0, drains retained RX and waits original TX.
Two RX slots retain owned packets until pop acknowledgement. A stop during
copy frees the private allocation; a full queue/allocation failure drops rather
than retaining borrowed pointers. The native side reconstructs a normalized
24-byte header only after checking address/fragment conditions.

The optional RX-diagnostics image adds hook-entry and post-validation counters
inside the same reservation; the scalar diagnostic build leaves eight bytes free. Such
counters are not peer identities. Profiles and counter addresses must come from
the exact generated image; do not infer them from a different candidate.

## Channel, admission and power

Scalar spans validate an owned packet interval before and after copying but
still use command `0x0086` once per 32-bit word. A 1 KiB body needs 256 data
commands plus control/ownership checks. The installed dev.19 profile uses this
path. Larger ESP-NOW frames alone do not remove that command overhead.

The optional dev.20 image adds actions `0x0100`/`0x0101`: an original eight-byte
header, action:u16, word_count:u16, address:u32 and data. The exact size is
`16 + 4*word_count`. Only aligned extant packet-data ranges are accepted; the
bulk copy never rings a control doorbell. Invalid requests return result2 and
a bounded 16-byte response. Scalar action1 STORE and other-action LOAD remain.
The immutable BLK1 marker and generated fingerprints qualify this protocol.
The bulk diagnostic build occupies the complete 1,900-byte reservation. Its
linker rejects any growth; it retains the same three packet-pool blocks. This
is radio-MCU reserved RAM, separate from the player's Linux system partition.

Request and response buffer limits must not be inferred from the host driver.
The driver has 2,048-byte buffers. Radio request accessor `0xbe6c` returns
`0xc00155b8`; event workspace `0xc0015b94` is only 1,500 bytes later. Original
`0xc036..0xc046` initializes that separate object and its internal link, while
`0xc130..0xc1b2` builds host events there. Original ingress `0xc3cc..0xc3d2`
copies `record_length-4` bytes into the request buffer; its outer 1,900-byte
check does not protect this boundary. Instruction replay shows 1,552 copied
bytes overwrite 52 event bytes; 1,500 copied bytes preserve the event link.
This proves a boundary before a live object, not a declared C array extent.

Native bulk IO consequently admits at most 371 words / 1,484 data bytes per
command. A 1,536-byte packet span is split into 1,484+52, preserving the same
complete-span ownership/ticket checks and a lease check for each command.
One 1 KiB span needs 21 RX or 17 TX commands including those checks. Partial
RX stays staged; failed writes enter existing abort/uncertain cleanup without
automatic fallback. This source profile is not hardware-throughput qualified.

Command `0x001d` is 48 bytes: LE16 action at +8 and channel at +10. Original
driver `0xc838..0xc87c` constructs that shape. GET (`0xde3c`) reads cached
`0xc0006624`; it is not independent tuner readback after sleep. SET invokes
`0xd8ac`, `0xd87c`, `0xcb88`, with RF programming through `0xed3c`/`0x4960`,
calibration/status handling, `0xefb4` and power-limit helper `0x5ed8`.
Action 2 is not a setter. The firmware truncates the input to eight bits, but
the native codec admits only actions 0/1 and channels 1..13.

Command `0x001b` GET reaches `0x88cc` / `0x48ec`, writes the RF register index
to `0x90000828` and reads `0x90000824`. Fixed indices `0x67..0x6a` provide a
separate tuning-register observation path, not calibrated frequency proof.

Pre-dispatch at `0x8078`, whitelist `0x3668` and feature check `0x4b80` precede
the switch at `0x8c9a`. Synthetic channel commands enter when `0xc0007859` is
0/1 and busy byte `0xc000edf4` starts clear; state 2 rejects with result 2.
An already-busy request retains status 4. The prologue sets its own busy byte,
so GET-polling that byte observes the diagnostic itself and cannot qualify idle.
Command `0x0021` actions `0x0030/31` alter `0x7859`, but seeded state tests do
not qualify actual wake transitions.

Linux ioctl admission checks adapter byte +`0x1404` clear and either +`0x13fc`
clear or +`0x13fd` set; bounded rejected cases return -16. Deep-sleep ioctl
`0x8bfb` has its own path: ASCII `0` requests wake, ASCII `2` queries through a
128-byte in/out buffer. Query returns `on ` / `off ` without NUL. The handler
can mask setter failures, so a wake needs explicit query and candidate checks.
Do not bypass admission by writing state bytes.

The exclusive startup order is LOAD_CANDIDATE, WAKE, VERIFY_CANDIDATE,
INITIALIZE, CONFIGURE. Shared mode instead borrows an already admitted native
radio and reads its actual channel; it does not reload/retune an active native
connection. [Wireless lifecycle](../sdk/WIRELESS.md) defines the matching stop,
sleep and USB contracts, including receive/sleep cleanup before manager release.

## Original loader and manager

The fixed unload job runs `/bin/sh /usr/local/bin/wlanapi.sh unload` with a clean
PATH including `/usr/local/bin`. Script SHA-256 is
`b1d7b114157a4a807ebfd8021fbc2aa413569905225aab75568773af852f26fb`.
The verified root has no `wlanapi.inc`; its appearance invalidates this profile.
Its return zero can mask a later rmmod failure; verify all four modules absent:
`sd8xxx`, `mp200_sdio`, `wlan_pm_register`, `wlan_pwr_ctrl`. Neither a normal
script exit nor software unload measures physical rail power.

Original `w8_proc_init` performs deepsleep 0, read-only NVP `zr11/1`, region
mapping/setregioncode, `tpccfg 0`, PA adaptation hostcmd and `txpower 15`.
`pa_cfg_ext_set` selects `0x007e`, action 1 / EnablePA 0 / empty `0x0114` TLV.
Radio validator `0xc000156c` and setter `0xc000141c` accept those controls;
EnablePA is not an established physical-amplifier switch. The adapter uses
bounded NVP capture and original execve arguments, with no NVP-write operation.

One controller process retains `cnmgr_init(NULL,NULL)` through its session.
Saved configuration is exactly 1,004 opaque bytes: getter request 24, ordinary
non-NULL connect request 7. It can contain credentials and stays in RAM, then
is wiped. Missing capture refuses disconnect; NULL/request-12 is not equivalent.
State 3 follows disconnect; prepare/connect and final state 4 precede fin.
Uncertain init/fin, owner mismatch and reentry forbid blind repetition.

The original daemon's recorded transition is connected internal 8, disconnect 9,
IP-stopped 10, WLAN-disconnected 2/public 3; prepare 3, connect 4, configuration
6, WLAN-connected 7, IP-ready 8/public 4. Manager RECONNECT has a state-4 shortcut;
that alone does not prove current association or authenticated host reachability.
Connect result 4/public 3 occurs on multiple failure/cancel paths and has no
unique inferred cause. Do not add automatic disconnect/reconnect loops.

USB CSTAT and sysfs function names alone do not establish user-volume authority.
`/proc/driver/udc` includes direct MMIO reads and is not a harmless poll source.
Use the qualified original lifecycle and independent retirement evidence.

## Espressif encryption observations

The measured S3/IDF 5.5.1 profile is explicit: nonce prefix 0, legacy subtype-
masked AAD, MIC8, Key ID 3, effective wire key AES-128-ECB(PMK, API LMK).
Generic management nonce `0x10` remains a separate primitive. API LMK alone
failed the retained physical vector. These findings do not define every IDF,
PMK initialization or peer implementation.

Pinned software `ccmp.c` SHA-256 is
`01296aa4c5b571fb003949b6da84d233b4c88b1b0c7beb2a896e860a6a680222`.
Its ESPRESSIF_USE fallback changes management nonce `0x10` to 0 and software
tag length 8 to 0. The native implementation still requires MIC8; software tag0
is not permission to accept unauthenticated frames. The reviewed receive wrapper
looks up IAV key and adjusts buffers; it does not itself execute AES.

| S3 static binding | Finding, not execution of S3 hardware |
| --- | --- |
| Vendor constructor/allocator | Constructor +`0x1d6` sets Protected `0x40`; TX metadata bit 0 / cipher bits 8:11; 64-bit counter increments, six PN bytes in eight-byte ExtIV at MAC offset 24 |
| Initial `.text.mt_set_lmk` | Halfword `0x0310` at context +184: key length 16 / ID 3; byte +186 is a separate hardware slot |
| Allocator +`0x9f` | Byte +185 shifted by 6 and ORed with ExtIV `0x20`, producing initial byte `0xe0` |
| CCMP descriptor | Words 3/8/8, callback relocations +16/+20 to encap/decap |
| Key install | `.text.mt_set_lmk` +`0x137/13a` -> `ic_set_key` -> `wDev_Insert_KeyEntry` -> HAL set/enable |
| HAL key slots | ESP32-S3 base `0x60034400`, stride 40, metadata words +0/+4, key bytes +8 rounded `(length+3)&~3`; validity at `0x60033814` |
| HAL crypto init | `0x30000` to `0x60033800/04`, clear +08/+0c/+10, OR `0x19` to `0x60033840`; management-RX query reads bit 17 from selector-dependent +00/+04 |

These addresses belong to ESP32-S3, not Sony. Vendor preparation reaches
`ieee80211_post_hmac_tx` / `pp_post` event 5. ppTask +`0x130` calls
`g_net80211_tx_func`, registered by output-init through
`ic_register_net80211_tx_cb` / `pp_register_net80211_tx_cb` as
`ieee80211_output_process`. Conditional `output_pending_eb` reaches `ppTxPkt`,
`ppProcTxSecFrame`, `ppProcessTxQ`, `lmacTxFrame` and the lower PPDU HAL.
Cipher selector 3 adds 12 bytes, consistent with MIC8 plus FCS4; that consistency
is not an independent MIC check. PLCP/duration/HTSIG/TXOP setup is not software CCM.

The slot's first word packs metadata bytes 3..6 (the supplied address prefix); the second combines
bytes 7/8 with control fields from bytes 0..2. Those numeric packings do not
identify nonce/AAD controls. The ordinary software encryption wrapper references
`wpa_crypto_funcs`; vendor preparation does not directly call it. Firmware
offload and the software fallback must therefore be analyzed separately.

`sta_recv_mgmt` +`0xa0a` reaches its ESP-NOW wrapper after Protected, DS, peer and
Key-ID checks; the wrapper advances 24 plus descriptor-header bytes and subtracts
header/trailer lengths. Earlier hardware security remains separate. The pinned
analysis uses Xtensa symbols, relocations and function-bounded disassembly;
it does not execute Xtensa objects under ARM/Unicorn.

Same-key restarts require non-reused TX PN and retained replay state. The
opt-in [link-key protocol](ESPNOW_LINK_KEYS.md) instead establishes fresh keys
and scoped volatile counters; it never resets old journals. Native TX callback
header observation is not independent over-air delivery proof.

## Analysis tools and evidence limits

`tools/espnow_known_key_frame.py` compares generic management, nonce-0 with the
same AAD, and nonce-0 with legacy subtype masking. Every result requires MIC8
and complete ESP-NOW decoding. Input is a 24-byte MAC header plus body, not
radiotap/pcap. `--fcs` strips four bytes without validating their CRC. Keys are
16 raw bytes or 32 hex digits in a private file; never put them in argv.
Default output excludes plaintext. `--output-payload` creates only a new work
file after exactly one profile authenticates.

```sh
.venv/bin/python tools/espnow_known_key_frame.py \
  --frame work/private-capture/action.bin --lmk-file work/private-capture/lmk.bin
```

Known-key PC vectors, compiled Thumb RX plus original `0x4b9c`, and full MAC-task
replays test different seams. Those replay fixtures model DMA/IRQ and admission
before the ring; they do not independently prove hardware capture. A recorded
60-second receive worker admitted 17 selected-source Protected frames without
installing the sender LMK. One retained 33-byte v2 frame passed MIC8 and matched
the known payload. This qualifies that S3/IDF setup, not every filter/power/key
state. A Protected bit or receive callback alone does not authenticate ciphertext.
Capturing one's own TX through a receive callback is not assumed.

Recorded physical tests include nonempty plaintext/encrypted lengths through
1,470 bytes, encrypted reverse traffic, process-restart reservations, stale-PN
and wrong-key refusals, with original restoration. They do not qualify every
shared Settings composition, long-duration load, sleep or USB. Exact scopes are
in [physical exchange reference](STOCK_WIRELESS.md#recorded-physical-exchange-scope)
and [status](../STATUS.md). Empty wire encoding is tested, but the standard peer's
zero-length send returned 12390 (ESP_ERR_ESPNOW_ARG) and empty delivery is unqualified.
